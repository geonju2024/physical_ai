MVP Design Considerations

드레스룸 환경을 고려한
설계 과제

다음 항목은 실사용 환경에서 점검할 과제와 MVP 대응 계획입니다. 완료된 현장 실증이나 측정 결과를 의미하지 않습니다.

설계 과제

집마다 다른 카메라 거리·배경

거울 앞의 인물과 주변 물체가 함께 촬영될 수 있습니다.

MVP 접근

MediaPipe + ToF 엣지 처리

카메라 영상은 거울에서 포즈 랜드마크·깊이 특징으로 변환하고, 원본 연속 영상은 외부로 보내지 않는 설계를 검증합니다.

설계 과제

옷 사진의 배경과 조명

스마트폰 조명과 의류 색상에 따라 배경 제거·색상 판독 품질이 달라질 수 있습니다.

MVP 접근

촬영 매트 + 크로마키

촬영 매트에서 배경을 분리하고 결과를 사용자가 확인하도록 해 간단한 등록 흐름을 구성합니다.

설계 과제

바쁜 아침의 응답 지연

매일 추천을 받는 경험에서는 지연과 외부 API 호출 비용을 모두 관리해야 합니다.

MVP 접근

규칙 기반 추천 + 캐시

FashionSigLIP 특징 벡터를 재사용하고 규칙 코드로 Top 3를 고르며, 실패 시 최근 코디 캐시를 보여주도록 설계합니다.

설계 과제

개인정보와 외부 AI 서비스

신체 영상, 의류 이미지, 가상 피팅용 사용자 이미지는 서로 다른 처리 정책이 필요합니다.

MVP 접근

목적별 데이터 경로 분리

일반 영상은 기기 내부에서 처리합니다. 옷 사진은 태깅 API로, 동의받은 사용자 이미지만 가상 피팅 API로 보냅니다.

End-to-End Pipeline

데이터가 개인화 코디가 되기까지

신체 영상은 Mirror Edge에서 MediaPipe·ToF로 처리하고, 옷장 이미지와 선호 정보는 MUSE Server / Partner API 경로로 구분합니다. 파트너 API에 사용자 이미지를 보내는 가상 피팅은 별도 동의가 필요합니다.

MVP Pre-Processing

6대 데이터 소스의 정돈 단계

원본 신체 영상은 거울 내부에 두고, 의류 사진과 파생 메타데이터는 용도별 처리 경로를 분리합니다. 각 처리 단계는 구현 및 품질 검증 예정입니다.

EDGE · RGB 입력

MediaPipe 신체 포즈

거울에서 카메라 영상을 처리해 33점 포즈 랜드마크와 신체 비율 특징을 추출합니다. MediaPipe 출력만으로 실제 신체 치수가 정확히 측정되는 것은 아닙니다.

IN거울 RGB 카메라 영상
OUT포즈·제스처·체형 비율 파생값
  1. 사용자가 거울 세션 시작신체 영상은 로컬 세션에서만 처리하는 방향으로 설계합니다.
  2. MediaPipe Pose / Hands 추론자세와 손짓 인식에 사용할 랜드마크·이벤트를 추출합니다.
  3. 입력 품질 확인가림·모션 블러·인물 프레임 밖 이탈을 감지해 재시도를 안내합니다.
  4. 파생 데이터 생성추천에 필요한 최소 신체 특징값만 서버에 전달하도록 설계합니다.
EDGE · 센서

ToF 깊이 보정

ToF는 신체 치수 추정에 활용할 깊이 정보를 제공합니다. 센서 구성, 설치 거리, 오차 보정 방식에 대한 실제 측정이 필요합니다.

INToF 깊이 프레임
OUT보정한 거리·체형 특징값
  1. 거리·깊이값 확인유효 촬영 범위와 반사·장애물의 영향을 확인합니다.
  2. RGB-Depth 정렬MediaPipe 포즈 좌표와 ToF 깊이값을 같은 기준으로 결합할 방법을 검토합니다.
  3. 신체 특징 산출추정 체형 비율·치수는 오차와 신뢰도를 함께 표시하도록 설계합니다.
  4. 개인정보 최소화원본 깊이 맵을 상시 업로드하지 않고 필요한 파생값만 사용합니다.
APP · CHROMAKEY + API

촬영 매트 기반 옷장 등록

옷장 등록은 모바일 앱에서 촬영 매트를 이용하고, 규칙 기반 크로마키로 배경을 제거한 뒤 비전 LLM을 1회 호출하는 방식입니다.

IN촬영 매트의 의류 사진
OUT의류 마스크·검증한 태그·패션 임베딩
  1. 의류 사진 촬영매트 위에 펼친 옷 사진을 사용자 동의에 따라 수집합니다.
  2. 크로마키 배경 제거그린/단색 매트와 옷의 경계를 분리하고 품질을 검사합니다.
  3. Vision LLM 태깅카테고리·색·패턴·핏·계절 정보를 미리 정의한 목록에서 고르고, 케어라벨 사진이 있으면 함께 읽습니다(별도 OCR 모델 없음).
  4. JSON 검사 및 사용자 확인소재 등 불확실한 속성은 빈값으로 남기고 사용자가 수정합니다.
  5. 의류 DB 등록원본 이미지·태그·FashionSigLIP 벡터를 필요한 범위에서 관리합니다.
SERVER / PARTNER API

쇼핑몰 상품 이미지

사용자가 확인할 상품 이미지·메타데이터를 별도 경로로 수집하고, 없는 옷의 유사 검색과 선택형 가상 피팅에 사용하도록 설계합니다.

IN사용 가능한 상품 이미지·메타데이터
OUT유사 상품 후보·VTON용 의류 이미지
  1. 상품 정보 사용 가능 여부 확인상품 이미지·사이즈·가격 정보는 라이선스와 이용 권한을 확인한 뒤 연결합니다.
  2. FashionSigLIP 임베딩보유 의류와 상품 이미지의 패션 특징 유사도를 계산합니다.
  3. 가상 피팅 선택VTON은 사용자가 명시적으로 요청할 때만 별도 처리합니다.
SERVER · RULES

날씨와 일정 기반 TPO

일상 컨텍스트를 모델로 다시 학습하지 않고 날씨·일정 정보를 간단한 규칙으로 필터링합니다.

IN날씨 API·동의된 일정 메타데이터
OUTTPO 태그·추천 후보 Top 3
  1. 외출 시간대 날씨체감온도와 강수 조건을 해당 시간대에 맞춰 조회합니다.
  2. 일정 분류사용자가 동의한 일정에서 격식·활동성 같은 최소 태그를 추출합니다.
  3. 의류 필터링체감 10℃ 이하 아우터 우선, 비 오는 날 스웨이드 제외 등의 초안 규칙을 적용합니다.
  4. Top 3 랭킹규칙을 통과한 코디를 개인 선호 벡터와 비교해 순위화합니다.
EDGE → SERVER

Wear / Pass 취향 업데이트

FashionSigLIP 모델 가중치를 다시 학습시키지 않고, 선택 이력의 패션 임베딩을 합산·감쇠하여 선호 벡터를 갱신합니다.

INWear / Pass 이벤트
OUT갱신된 선호 벡터와 랭킹
  1. Wear / Pass 선택 기록반응과 옷 아이디·시간을 간결한 이벤트로 기록합니다.
  2. 중복 입력 방지버튼 연타 등 우발적인 반복 이벤트는 병합합니다.
  3. 60일 시간 감쇠 정책오래된 선택의 반영 비중을 낮추는 규칙을 실험합니다.
  4. 다음 추천에 반영옷의 선호 유사도와 TPO 규칙을 다시 결합합니다.

MVP Core Philosophy

MUSE가 지향하는
4대 원칙

  • 01. 원본 신체 영상은 거울에서 처리합니다일반 포즈 분석 영상은 기기 외부로 보내지 않는 구조로 설계합니다. 가상 피팅 이미지 전송은 별도 동의를 받은 경우에만 가능합니다.
  • 02. 사용자 데이터는 목적에 맞게 분리합니다태깅 API에는 옷 사진을, 추천 서버에는 필요한 파생 정보를 전달하도록 설계하며 API 보관·학습 정책을 검토합니다.
  • 03. 내가 보유한 옷을 우선 추천합니다일상 코디는 디지털 옷장에 등록된 의류를 중심으로 만들고, 미보유 상품은 선택형 가상 피팅으로 구분합니다.
  • 04. 오류가 발생하면 안전하게 되돌아갑니다태깅 실패는 사용자 확인으로, 추천 API 지연은 코디 캐시로, 피팅 결과 품질 저하는 상품 정보 안내로 전환합니다.
